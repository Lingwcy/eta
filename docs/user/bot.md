# 连接 Bot，在云端工作

手机可以通过 [eta-mobile](mobile.md) 连接 Bot，继续会话、查看任务进度和处理审批。

先部署 Eta Bot，并配置工作空间根目录。在 Desktop 的「设置 → 应用 → Bot」中填写服务器地址及访问令牌，保存并连接。随后在 Bot 配置中点击「导入客户端凭证」，将客户端已保存的 API Key 或 OAuth 凭证导入 Bot，模型列表会立即刷新。重复导入会更新同一服务商的凭证，也可单独移除 Bot 上的凭证。

新聊天中，将执行位置从「此计算机」切换为「云端」，再选择云端项目，或通过「新建云端项目」在 Bot 根目录下创建同名文件夹。根目录下已有的项目文件夹也会自动显示，云端项目的可见范围限于这个根目录。任务使用 Bot 上的文件、模型和技能；侧边栏会将本地项目与云端项目分组显示。

已有会话保持原来的执行位置。本地与云端的文件和会话历史不会自动同步。关闭 Desktop 不会停止云端任务；需要停止时，在对应会话中操作。

云端会话也使用[沙盒策略](sandbox.md)。新会话默认使用工作区沙盒，审批卡片在 Desktop 和 Mobile 中显示。Bot 是否[自动审查](sandbox.md#自动审查)越界请求由 Bot 配置文件中的 `runtime.approvalReviewer` 决定，本机的审批人设置不影响 Bot。Bot 管理员通过配置文件中的 `allowedSandboxModes` 决定允许的策略；不设置时三种模式都允许，包括完全访问。官方服务器部署工作流的 `enable_full_access` 默认是 `false`，会移除完全访问；未设置允许列表时只允许 `read-only` 与 `workspace-write`，设置为 `true` 才会加入完全访问。若显式默认模式与开关冲突，部署会改用允许的受限模式；若原本只允许完全访问，则回退到 `read-only`；显式空或包含无效值的允许列表会被拒绝。修改本机的默认策略不会修改 Bot 的配置。

Bot 默认使用 Code mode 组合调用工具。管理员可将 `runtime.agentMode` 设为 `"standard"` 使用普通模式，或设为 `"codemode"` 恢复 Code mode；修改配置后重启 Bot。新任务使用当前配置，恢复未完成任务时保留其原模式。Desktop 的权限页显示 Bot 实际配置，本机的 Agent 模式选择不影响 Bot。

连接中断时，Desktop 保留已读取的云端项目和会话目录，并尝试重新连接。也可在 Bot 设置中手动重新连接或断开连接。本期支持连接一个 Bot，Bot 不会默认创建项目。

## Git 工作区与 GitHub

Desktop 连接 Bot 后，可以在新聊天的工作区配置中创建服务器上的 worktree，并查看该项目所选 GitHub remote 的 PR 与 Issue。管理目录位于 workspaceRoot/.eta-worktrees，不会作为新的项目扫描。

GitHub 访问使用服务器已有的 GitHub CLI 登录；公开仓库也支持匿名访问。私有仓库需要在服务器运行 gh auth login。

## 定时任务

支持定时任务的 Bot 可在 Desktop 的定时任务视图中管理计划，关闭 Desktop 后仍会在服务器运行，受并发上限和项目范围约束。请保持 Bot 进程运行。执行内容使用原会话的工作区、模型和审批策略，不会在客户端本机执行。

Agent 创建和管理的计划直接生效，无需批准。Desktop 的工具消息显示结果并可取消计划，也可从左侧定时任务菜单管理。无 Desktop 连接时，管理员可携带访问令牌查询 `/v1/schedules`，获取生效计划及未决请求；结果未知时查询 `/v1/schedule-requests/:requestId`。写入结果为 `pending` 时还在核对，不代表已暂停或删除；同一请求重试必须使用相同参数和身份。

忙时只补发最近一次，默认补发窗口为 24 小时，失败不自动重试。计划暂停或删除不会中止已开始的聊天任务。归档会话暂停计划，恢复不会自动重新启用。

Bot 重启后会恢复可安全继续的任务。如果定时执行中断在不能安全重放的工具调用上，会取消当次执行并保留记录，后续计划继续运行；缺少任务定义时仍需管理员处理。普通聊天中的中断工具保留人工恢复流程。

模型额度耗尽等错误会记录为当次执行失败，定时计划仍然有效。Bot 会释放已失败执行的占用，后续轮次继续尝试；额度恢复后无需重新启用计划。
