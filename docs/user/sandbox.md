# 选择代理的访问范围

在聊天输入框中选择「只读」「工作区沙盒」或「完全访问」。新会话默认使用工作区沙盒；可在「设置 → 权限」修改之后创建的本机会话的默认策略。已有会话保存自己的策略，切换前需要停止线程及其子智能体。子智能体继承主会话的策略。

在「设置 → 应用 → 权限 → Agent 模式」选择工具调用方式。默认的 Code mode 让 agent 用 JavaScript 组合调用已启用的工具；普通模式让模型直接调用工具。两种模式共用工具开关、审批和系统沙盒。切换从下一轮新任务生效，已有会话无需重建；执行中及待恢复任务继续使用原模式，子 agent 继承父任务的模式。Code mode 无法运行时，可切回普通模式再发起任务。

- **只读**：代理可以检查工作区文件。编辑文件和运行命令前需要审批。
- **工作区沙盒**：代理可以在工作区内读写文件、运行本地命令并联网。访问工作区外的文件需要审批。
- **完全访问**：移除代理文件工具和命令的文件系统及网络边界，可访问电脑上的文件和互联网，包括 Eta 数据目录。此模式不保证定时任务存储的文件隔离；需要该保护时请使用受限策略。

待审批卡片会显示操作、完整参数，以及额外的读取、写入和联网范围。选择「批准一次」或「拒绝」。批准不会改变会话策略，通常也只授权这一次工具调用。停止任务或重启 Eta 后，已经批准的临时权限失效；未完成任务不会自动恢复。

## 自动审查

越界请求默认先交给审查模型，使用会话自己的模型。正常开发所需的拉取远端更新、安装依赖、提交、推送任务分支和创建 PR 通常自动批准；只有存在明确危险的操作才会拒绝。自动审查只决定是否批准，不会扩大请求的范围；有无法确认的实质风险、审查出错或超时的请求会交给你，并附上原因。涉及其他仓库的 Git 元数据或整个主目录的请求仍由你决定。可在「设置 → 权限 → 越界请求审批」把审批人改为「我」，恢复逐次人工审批；已有的人工审批选择不会被覆盖。

审查模型默认使用发起请求的会话自己的模型，也可以指定其他模型；指定的模型不可用时，请求会交给你。审查器只能读取当前工作区和本仓库的共享 Git 目录，并可运行只读 Git 查询；不能读取本次申请的其他外部路径，也不能联网，用量计入该会话。被拒绝时，代理会收到理由并尝试更稳妥的做法；连续被拒三次后，后续请求交给你。任务运行期间，审批区域的「自动审查记录」列出自动作出的决定。设置页显示最近的审查统计，审查记录只保存在本机，不包含文件内容。

## 联网与代理

工作区沙盒默认允许联网，命令会继承启动 Eta 时的 HTTP、HTTPS、SOCKS 代理和绕过列表（`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`，也支持小写）。macOS 未设置代理环境变量时会读取系统的静态 HTTP、HTTPS 和 SOCKS 代理；仅启用 PAC 自动配置时，请向 Eta 提供本地代理端口对应的环境变量。代理不会绕过禁用联网的策略。

沙盒不会自动继承主机的 GitHub token、SSH 私钥或整个主目录。需要登录状态来推送或创建 PR 时，代理仍需申请相应配置路径的访问权限；受保护的凭证目录不能通过普通批准解除限制。

## 在 worktree 中提交

在 Git worktree 中，代理提交改动需要写入主仓库的 Git 目录。卡片会显示为「Git 写入」，授权范围只包括该 worktree 自己的记录、对象库、远端跟踪引用、标签及当前分支所在的 ref 目录（同目录下其他分支也可写），不包括仓库配置和 hooks。选择「本次运行内允许」后，本次任务中相同范围的 Git 写入不再询问；任务结束、停止或切换沙盒策略后失效。把审批人改回“我”会撤销自动审查发出的运行内授权，您自己批准的运行内授权仍保留。期间任何申请该范围的命令都能写这些 Git 目录，请只在信任当前任务时使用。查看状态、日志和差异不需要批准。

受限策略允许访问运行命令所需的系统程序和库，以及会话的临时文件。Eta 的数据目录和常见凭证目录仍受保护。沙盒约束代理的内置文件工具、命令及子进程；Eta 连接模型服务和 Bot 收发消息仍使用主程序的连接。

macOS 和 Linux 支持受限执行。Linux 需要可用的系统沙盒后端；Bot 镜像包含原生后端。当前 Windows 版本尚不支持受限执行。后端缺失、内核不支持或启动失败时，Eta 会显示原因并阻止任务，历史仍可查看。Eta 不会自动改为完全访问。
