# 用 Eta 完成工作

[English](desktop.md) · 简体中文

安装和首次使用请看 [README](../../README.zh-CN.md)。

## 界面语言

在**设置 → 应用 → 外观 → 语言 / Language**选择「简体中文」或「English」。保存后立即应用到所有 Eta 窗口，重启后保留。界面语言不会更改已有聊天内容，也不会指定 agent 的回复语言。

## 聊天与本地数据

需要一边聊天一边查资料时，使用 **Cmd/Ctrl+T** 打开网页标签，在地址栏输入网址或搜索内容。

**新聊天**会继承当前聊天的工作区；如果该工作区已有未提交的聊天，就返回并保留其草稿。从网页或设置标签发起时，沿用最近的聊天上下文。切换标签会保留各自的草稿；关闭聊天标签不会删除历史，已提交的任务也会继续执行。使用 **Cmd/Ctrl+W** 关闭标签，**Cmd/Ctrl+Shift+T** 重新打开。

显示灰色“选择项目”时也可以直接发送消息。Eta 会为该聊天创建独立的临时工作区，重启后仍保留文件，直到永久删除聊天。发送第一条消息前，可悬停项目名更改项目，点击项目旁的叉号或菜单中的“不在项目中工作”清除选择；清除不会丢失草稿和附件。从无项目聊天发起的新聊天也保持无项目状态。

项目较多时，可通过左侧铃铛打开「最近聊天」，跨项目查找最近发送过消息的聊天。列表按成功发送新输入的时间排序并保存在本机，打开会话和后台任务更新不会改变顺序；再次点击铃铛返回项目列表。

右键已保存的聊天，可以重命名、调整项目归属、归档或恢复、在新的 Eta 窗口中打开，以及永久删除本地历史。删除会先停止会话及其子任务，再移除历史。调整项目归属不会改变 agent 执行任务的目录。“打开方式”可用默认或指定应用打开主会话 JSONL 记录，建议使用文本编辑器查看。

在**设置 → 应用 → 存储**中查看本地会话占用，并定位会话目录，便于检查或备份。

备份时保留整个会话目录，不要只复制主 JSONL 记录。子智能体共用这份记录，恢复任务还需要同目录的状态文件。打开未完成的会话时，需要明确选择恢复或停止。

## 定时任务

打开左侧「定时任务」并选择「新建任务」，指定执行工作区、内容和时间；也可右键已有聊天选择「添加定时任务」。计划留在该聊天中，按会话聚合显示，通过左侧任务菜单编辑、暂停、恢复、运行一次或删除。支持一次、间隔、每天和每周；间隔至少 5 分钟，按当前机器时区保存。

Agent 创建和管理的计划直接生效，无需单独批准。工具消息会提示结果并提供取消计划的操作，也可随时从左侧任务菜单管理。新建任务时可在「高级」选择模型与权限，新任务会话默认完全访问，也可切换到工作区沙盒；已有会话沿用当前权限，直到你主动修改。编辑计划时可在任务运行期间保存模型与思考级别，新配置从后续模型请求生效，已发出的请求继续使用原配置。自动执行使用该会话的模型、工作区与审批设置，可能修改文件和消耗模型额度。

忙时不打断现有任务，空闲后只补发最近一次，超过默认 24 小时的执行不会补发。执行失败不会自动重跑。归档会话暂停计划，恢复会话不会自动恢复计划；关闭聊天标签不暂停计划。暂停计划只停止后续触发；手动删除计划会先停止该会话及其子任务，再移除计划。管理请求显示「正在处理」时，原计划状态仍有效，等待核对结果后才会显示成功。「立即运行」遇到该会话中断时，会结束未完成的旧轮次，使用当前计划内容开始新一轮；历史记录和计划时间不变。

Eta 退出或电脑睡眠时不会执行；重新打开后按上述补发策略处理。macOS 关窗后保留运行。Windows 默认关窗退出，可在「设置 → 应用 → 关于 → 后台运行」开启「关闭窗口后后台运行」，通过可见托盘打开或退出。显式退出始终停止本地任务。

Bot 计划保存在服务器，Desktop 断线或退出不会停止它们。断线时显示可能过期的缓存，不能创建或修改；需要支持定时任务的 Bot 版本，不会改到本地执行。实际工作区不可用或会话需要恢复时，任务显示阻塞，处理后再继续。

## 在独立 worktree 中开始

发送新聊天的第一条消息前，可在项目旁的工作区配置中开启“新 worktree”，通过分支菜单选择已有分支或填写新分支名。Eta 在发送时创建独立目录；当前目录未提交的改动不会带过去。创建或发送失败时保留草稿，重试会复用已创建的工作区。已被检出的分支和远端跟踪分支作为新分支的基线。会话发起后工作区配置自动隐藏。

Git 写入的审批和本次运行内授权见[访问范围说明](./sandbox.md#在-worktree-中提交)。关闭聊天标签或归档会话不会删除 worktree。

Desktop 默认把 worktree 存放在 Eta 数据目录旁的独立管理目录，保护整个数据目录；已有会话的执行目录不会自动迁移。

## 查看 GitHub PR 与 Issue

右侧栏有可用内容时默认展开。选择 GitHub 标签后，在顶部功能区切换 PR / Issues，默认查看 Open 列表；选项菜单中保留仓库选择、状态筛选、刷新和访问状态。点击条目在外部浏览器打开。项目有 GitHub remote 且宿主支持查询时才显示 GitHub 标签；当前会话有子智能体时才显示子智能体标签。查看仓库以会话的实际执行工作区为准。**Alt+←** 折叠或重新打开当前右侧栏，也适用于网页与设置标签。

公开仓库可匿名查看；私有仓库或更高访问额度需要在本机（Bot 项目则在服务器）运行 gh auth login，然后刷新 GitHub 侧栏。GitHub 访问身份独立于模型的 GitHub Copilot 登录。Bot 未连接时缓存标为过期，刷新及写入不可用。

## 技能

技能为 agent 提供可复用的指令。每个技能放在一个包含 `SKILL.md` 的文件夹中：

| 适用范围 | 目录                       |
| -------- | -------------------------- |
| 个人     | `~/.agents/skills/`        |
| 当前项目 | 项目内的 `.agents/skills/` |

同名技能以项目版本优先。在**设置 → 技能**中添加自定义目录、查看发现错误、启用或停用技能，以及打开技能文件夹。打开尚不存在的技能目录时会自动创建。

通过输入框的技能入口、**Cmd/Ctrl+Shift+K**，或在请求中写出技能名来选择：

```text
$better-readme 重构这个项目的 README。
```

这个例子需要先安装名为 `better-readme` 的技能；Eta 不自带该技能。

Eta 先向 agent 提供技能名称和描述，使用时才加载正文，再按需读取附属资源。已加载的指令会随会话保存，重启和压缩上下文后仍可使用。要加载更新后的版本，先在输入框中移除已加载的技能，再重新选择。技能使用当前可用的工具和本机依赖，不会获得额外权限。

在「设置 → 应用 → 权限 → Agent 模式」选择工具调用方式。默认的 Code mode 让 agent 用 JavaScript 组合调用已启用的工具，普通模式让模型直接调用工具。两种模式共用工具开关、审批和系统沙盒。切换从下一轮新任务生效，已有会话无需重建；执行中及待恢复任务保持原模式，子 agent 继承父任务的模式。Code mode 无法运行时，可切回普通模式再发起任务。Bot 的模式由服务端配置决定，连接后会在权限页显示。

## 实验性桌面控制

macOS 14 及以上版本中，在「设置 → 权限 → Computer use」开启桌面控制，即可让主 agent 在本地聊天中读取应用控件并操作应用，无需重启。开启时也会允许图片访问。首次使用请按页面提示在 macOS 系统设置中允许屏幕录制和辅助功能，并选择支持图片的模型；操作系统可能要求重启 Eta 以应用系统权限。直接让主 agent 操作桌面即可，普通模式和 Code mode 均可使用。agent 优先读取目标应用提供的控件信息，需要视觉判断时再查看截图，无需配置额外定位模型。截图只显示选定窗口，即使它被其他应用遮挡；输入定向发送给目标窗口，不移动系统鼠标。截图中的紫色光标表示 agent 的操作位置。操作期间会显示可拖动的预览浮窗，随观察和操作结果更新；点击浮窗的 × 可停止本次桌面控制。紫色光标和短暂点击圈也会出现在目标当前可见的位置，不移动系统鼠标。停止任务或关闭权限时，浮窗和屏幕标记一起消失。目标位于另一个 Space 时，截图可能不包含菜单和子窗口；agent 会收到范围提示，并通过控件编号操作它们。使用桌面控制时，macOS 必须保持登录并解锁。各应用对后台输入的支持程度不同，重要操作后应检查实际结果。未充分提供控件信息的应用可能需要更多截图操作。停止任务会取消桌面操作，并释放本工具按下的键鼠。

菜单栏应用也可以直接交给 agent 操作：它会选择对应图标并打开菜单或弹出面板，面板可能显示在你当前桌面上。你查看或手动操作应用不会永久终止任务；界面变化后，agent 会重新观察再继续。

如果你正在前台使用同一应用的其他窗口，Eta 会停止输入，避免转移你的键盘焦点。桌面操作可以影响其他应用，不受工作区文件沙盒约束。只有本地 Desktop thread 的主 agent 可以控制电脑，orchestrator 模式下也由主 agent 操作；占用期间，其他 thread 会收到忙碌结果。

## 子智能体

主 agent 可以将工作交给子智能体，在独立子会话中执行。有委派任务后，使用 **Alt+←** 打开右侧栏，选择任务查看对话和已汇报的进展。执行中也可发送消息调整方向或请求汇总；向已结束或暂停的任务发消息，会继续同一个子会话。

独立子智能体接收交给它的任务与项目指令；分叉子智能体会继承创建时的对话历史。

在**设置 → 子智能体**中创建预设，设置任务指令、思考级别和候选模型。执行任务的子智能体默认直接完成工作；需要协调其他智能体的预设可开启继续委派。模型范围默认跟随当前主模型，可通过模型选择器启用其他模型。嵌套深度和并发上限为全局设置；并发按各会话的智能体树单独计数，超出的子任务会排队。

| 模式 | 委派方式                                       |
| ---- | ---------------------------------------------- |
| 按需 | 主 agent 在有需要时委派任务。                  |
| 编排 | 子智能体执行工具，主会话负责交流、协调和汇总。 |

编排模式下，主会话在协调回合之间可以接收新消息，子任务继续执行。子任务结束时，主会话会自动被唤醒并汇总结果。

等待超时不会停止子任务。停止任务会取消执行，不会生成最终答复，但会保留已汇报的进展和历史。停止主任务会停止整个子任务树。要继续未完成的工作，请明确恢复，或在停止后发送新任务。
